# design-diff — 拿 figma 导出的那一帧当地面真值

```bash
python3 tools/design-diff/check.py <screen.ui.json> <figma-export.png> [--heat out.png]
```

## 它补的是哪个洞

README 那张四端对照表里的每个数字,量的都是「各引擎 vs figkit 自己的 HTML 产物」。
它证明的是**四端一致**,不是**忠于设计稿** —— 而这两件事不一样:capture 只要把设计读错了,
四个后端会**一致地**错,全套测试照样绿。

本仓在别处写过一句话:*「一致不是正确:两家一起折成 min(w,h) 照样全绿,而 CSS 说非正方形的
50% 是椭圆角。」* 那句话往上再推一层,落点就是捕获层自己 —— 而在这支脚本之前,那一层没有
任何东西守着。

## 怎么读它给的数

误差被拆成**文字内 / 文字外**两半,因为这两半的性质完全不同:

- **文字内**:figma 有自己的字形栅格化与 hinting,浏览器有另一套,同一个字永远差一圈。
  这部分是噪声,不该当指标看 —— 但它**有一个用处**:**字体掉档的警报**。某端要是加载不到
  设计字体、悄悄退回系统字体,版面还是那个版面,「文字外」按定义一动不动,跳的是这一栏。
  (实测踩过:引擎工程里躺的是翻译前那份中文子集,英文的字它盖不住,Unity/Godot 于是
  整屏走了回退字体 —— 对 HTML 的**全帧**差从 1.7 涨到 4.0,而「文字外」纹丝不动。)
- **文字外**:几何、颜色、圆角、描边、图片有没有落在设计说的地方。**真正说明问题的是这个。**

实测(邮件示例三屏,figma 1× 导出,四端各自渲;单位 /255,全是**文字外**):

| 屏 | HTML | Unity | Godot | Cocos |
|---|---|---|---|---|
| 列表 | **0.81** | **0.81** | **1.13** | **1.13** |
| 详情(有附件) | **0.53** | **0.59** | **0.65** | **0.57** |
| 详情(无附件) | **0.59** | **0.62** | **0.63** | **0.63** |

基准帧就在 `figma2html/examples/mail/design/`,克隆下来照着跑即可:

```bash
python3 tools/design-diff/check.py figma2html/examples/mail/screen-list.ui.json \
                                   figma2html/examples/mail/design/screen-list.png
```

这张表**是拿它当尺子改出来的**:第一版量出 Godot 列表 1.21 / Cocos 1.34,顺着数去看,
撞出两条真缺陷 —— Godot 把非正方形的 `radius:50%` 画成胶囊(`corner_radius` 是标量),
Unity 与 Cocos 干脆丢掉**带模糊**的阴影。补完各降到 1.13 / 0.81 / 1.13。
四端互比时这两条都看不见:三家一起没有那片投影,差值反而是 0。

同一批的**全帧**数是 5.0–6.0 —— 差了一个数量级,而两者量的是同一张图。原因就是拆分的
理由本身:示例是英文的、设计稿是中文的,全帧那栏于是主要在量**翻译**;而后两屏几乎全是
正文,这一栏还会随每次改文案上下跳,被它判分的版式却一动没动。只报一个数会把这件事说反。

**跨语言凭什么还能比**:文字外这半对文案不敏感 —— 拿翻译前的中文 IR 把四端重建重渲一遍,
十二格里十一格挪动 ≤0.02。前提是**译文仍装得进设计量给它的盒子**(见下面第 4 条)。

**引擎侧怎么喂**:各自渲出帧原尺寸的 PNG,再 `--rendered <png> --label <名字>` 交给本脚本,
它不去认那四套构建管线。

## 四条使用要求(踩过才写下来的)

1. **导出必须是 1×、帧原尺寸。** 导 2x 再缩回来会引入一次重采样,量出来的全是它。
2. **屏与导出必须是同一个变体。** 设计稿改过之后再导,比的就是两份内容。实测:某一屏的
   奖励格在新版里换了品质底色与数量、勾的美术也换了,均差从 1.2 跳到 **4.2** ——
   与渲染保真毫无关系。数字异常时先怀疑这条。
3. **渲染走 `render.js`**,不是 capture 顺手产的 `.tree.html` 预览。那两套贴样式逻辑是
   平行实现,比错了就答非所问。
4. **文案必须装得进设计给的盒子。** 文字那半是按 IR 里每个文字元素的盒子(外扩 4px)遮掉的,
   字一旦长过盒子,溢出去那截就落进「文字外」,被当成几何误差报出来。实测:示例译成英文后
   正文多绕了一行,详情屏从 **0.53 跳到 0.82**,渲染一个像素都没动。所以这条不靠记性 ——
   `tools/html-smoke/` 会在真浏览器里逐个量示例里的文字,装不下就红。

## 依赖

Pillow 与 Edge/Chromium(找不到就设 `EDGE_PATH`)。所以它在 `tools/` 而不是任何 skill 里 ——
skill 必须能单独安装且零依赖。本目录不参与 `run_all_tests.py`。
