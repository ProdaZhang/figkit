# Verification log

The status matrix in the README says *what* has been verified in each engine and how far
the pixels are off. This file is the long version: what running a real Figma capture through
an actual engine actually found, in the order it was found.

It is kept out of the README on purpose. The matrix is what a visitor needs in ten seconds;
this is what someone needs before touching that backend — and the two grow at different rates.

## figma2godot — Godot

✅ **Godot 4.3**, re-verified on **4.7.1** (2026-08-04): both examples still render clean, zero engine errors. That same 4.7.1 run was also the first time the compiler was fed a **real Figma capture** rather than a synthesised fixture, and it immediately surfaced a bug the fixtures cannot reach: Figma component-instance ids carry semicolons (`I25:4109;206:12513;202:12604`), and `sub_resource` ids accept only `[A-Za-z0-9_]`, so every StyleBoxFlat and Gradient on an instanced element failed to register and those elements rendered unstyled. Fixed and now asserted. A second real-capture run on 2026-08-05 found the other thing fixtures cannot reach: Godot's `clip_children` **cannot nest**, so when rounded clips nest the compiler has to pick one, and it was picking the innermost — which left the outer panel clipped by a rectangular scissor and its 80px bottom corners squared off against the background. It now gives `clip_children` to the **outermost** clip on each ancestor chain (the outline is what the eye reads; inner clips sit inside an already opaque parent) and degrades the inner ones to a rectangular `clip_contents`, logged as known-loss. The login and mail shots in the README are a **real pixel comparison** against HTML — mean 2.2–3.9/255, under 2.5% of pixels off by more than 24, all of it on glyph edges (the two shots used to be at different scales, which looked fine and compared to nothing; `shoot_stage.py` fixes that). Motion runs in-engine and was **screenshotted mid-transition** — curves agree with Python and Unity to 6 decimals at a non-key point, and the frames caught a backdrop bug no numeric check could see. **The v1.1 `@in:` branch added on 2026-07-31 has not been through an engine run** — it is held by source-level conformance assertions only, and this row will stay qualified until someone re-runs the engine. A 2026-08-05 pass rebuilt all four mail screens from the shipped (English) IR and measured them against the **Figma export** rather than against HTML, which named the defect the backend-vs-backend table could not: `radius: 50%` on a non-square box was drawing as a capsule, because `corner_radius` is a scalar. Solid-filled elements of that kind now compile to an `.svg` with true elliptical corners — the same route v1.2 vectors already take, so no new machinery — and radial gradients stopped collapsing to their average colour (`GradientTexture2D` has a `FILL_RADIAL` mode; the UV circle becomes an ellipse when stretched, which is exactly CSS's default `ellipse at center` / `farthest-corner`). Outside text, the list screen went **1.21 → 1.13/255** against the design.

## figma2unity — Unity

✅ **Unity 6000.4.8f1**, and re-run end-to-end on **2022.3.62f3 (2026-08-05)** — this time in an actual **built Windows player**, rendering to a 1080×1920 RenderTexture, not just a batchmode import check. That run caught a bug no import check could: USS selectors are CSS class names, so only `[A-Za-z0-9_-]` is legal, but the sanitiser only replaced `:`. Figma component-instance ids carry `;` and figkit's own mask-wrapper ids carry `~`, and **a single invalid selector voids the entire stylesheet** — 129 rules, none applied, every element resolving to 1080×0 transparent, the whole screen black. Fixed and asserted. With that fixed the player renders the real screen, and the three v1.2 features it used to drop are now implemented rather than declared away: `paths` are **drawn** by `runtime/FigVector.cs` through UI Toolkit's Painter2D (real vectors, no bitmap assets and no extra package), `clip` maps to `overflow: hidden` (which in UI Toolkit already follows `border-radius`, so rounded clipping is free here), and hard shadows plus `borderAlign: outside` become sibling boxes laid underneath — USS has no `box-shadow`, but "another box of the same shape" is exactly what those two are. A follow-up run on 2026-08-05 closed two more: Unity clamps `border-radius` **per axis** where CSS scales all four corners by one factor, so a 57px radius on a 235×42 box came out as a stretched olive instead of a capsule — the compiler now applies the CSS rule itself before Unity ever sees it; and Painter2D turned out to join the contours of a multi-contour path into one polygon, which shredded every stroke band into thin triangles, so disjoint contours are now filled one at a time (overlapping ones still share a fill so holes survive). A third run on 2026-08-05 fixed two more, both found by looking at pixels rather than at code. figkit had never emitted **texture import settings**, so every PNG came in on Unity's 3D defaults: mipmaps on, DXT compression on, `alphaIsTransparency` off. UI art is blitted 1:1 but the sampler still dropped to a lower mip, so edges bled — a white tick came out a pixel fatter on every side with its bottom row sheared flat, while gold stars in the same cell came out a pixel thinner (bright spreads, dark shrinks, one cause). `runtime/Editor/FigkitTextureImport.cs` now pins those, and the tick matches HTML **row for row**. And gradients are no longer declared away: USS has no gradient property, so the converter **bakes a PNG at compile time**, projecting each texel onto that element's real gradient axis — no runtime code for the integrator, output still byte-deterministic. Measured against the HTML build on the same 1080×1920 frame, the mail panel went **11.01 → 6.55 → 5.55 → 5.54 → 2.60/255** on the list screen and **8.41 → 7.27 → 6.86** on the claimed-reward screen — the last step being the shared design font. **All four backends now render in the design font.** `scripts/subset_font.py` instances the two weights out of the variable source (its `wght` axis defaults to **100/Thin**, so referencing it directly gives a whole screen of hairlines while the design calls for Bold 700) and subsets to the characters the screens actually use — 39KB per weight, 19KB as woff2. Before that, each backend fell back to its own system font and **even the line breaks disagreed**, so a pixel comparison measured little except glyph noise. One trap on the way: with a real Bold face loaded you must **stop emitting `-unity-font-style: bold`**, or Unity synthesises a second bold on top of it (the title's ink went 1930 → 2613 pixels). INSIDE stroke bands are no longer a Unity problem at all — capture now splits Figma's ±w band into a fillable ring, so no backend needs boolean clipping. What is still declared lost: blurred shadows. The CJK font now ships with the conversion (`fonts/FigCJK-{Regular,Bold}.ttf` next to the USS); an integrator who wants a different face swaps those two files. C# compiles zero-warning; both examples' UXML/USS pass Unity's importer with CloneTree structure asserted (main screen: 37/29/13 elements, nesting and copy intact, 12-cell grid present); `motion.json` loads as `AnimationCurve`s agreeing with Python **and Godot** to 6 decimals (visual pass in Play Mode still pending). A 2026-08-05 pass rebuilt the player from the shipped (English) IR and measured it against the **Figma export** instead of against HTML. That reframing paid for itself immediately: the biggest remaining gap was not geometry at all but **blurred shadows**, which USS cannot express and which this backend had been dropping outright — and a card UI is mostly blurred shadows. They now bake at compile time into a PNG shown under the element, alongside the hard-shadow and stroke-ring underlays that were already there: a rounded-rect coverage mask (per-axis elliptical corners, one-pixel antialiasing) run through three box passes ≈ a Gaussian at σ = blur/2, which is CSS's own definition of the blur radius, on a canvas inflated by 3σ so the falloff is not clipped. Content-hashed, so six identical cards share one file. Radial gradients bake through the same path now as well. Outside text, the list screen went **1.01 → 0.81/255** against the design — level with the HTML renderer. **Not re-run since 2026-07-31** for motion, which changed `Play`/`Wiggle` to read `TimerState.now` and added the `@in:` branch; those lines are source-level only so far.

## figma2cocos — Cocos Creator

✅ **Cocos Creator 3.8.8** (2026-08-05) — built for `web-desktop` from a real Figma capture and **screenshotted at 1080×1920**, mean **6.21–8.93/255** against the HTML build on the same frame, the same order as Godot and Unity. Getting there took three bugs that only a real engine can show. (1) `new Node()` lands on `Layers.Enum.DEFAULT` while the UI camera only draws `UI_2D`, so the whole tree built correctly, every component present, and **not one pixel appeared, with no error** — nodes now inherit their mount point's layer. (2) The Creator build pipeline runs Babel, and a conditional whose one branch is inferred as a Flow annotation makes `createTSUnionType` throw, which fails **the entire script**, invisible to `tsc` because `tsc` never runs Babel. (3) `Graphics.arc` is not canvas's `arc`: its first point is a `moveTo`, so it **always starts a new sub-path** instead of continuing from the current point, and `counterclockwise=false` sweeps *decreasing* angles — so "straight edge + four corner arcs" became four disjoint sub-paths filled as one polygon (every rounded box shredded into diagonal wedges) with the reversed sweeps drawn as giant loops. Corners are cubic Béziers now. All three are pinned by source-level guards. A second pass the same day closed three more that only pixels show: `UIOpacity` turns out **not to affect Graphics at all** — not on the node, not cascaded from an ancestor — so an `opacity: 0.38` white decoration painted as opaque white and smeared the whole title bar; Graphics colours now carry the entire ancestor chain's opacity (an in-engine probe settled it: `fillColor` alpha works, both `UIOpacity` spellings read pure 255). `border-radius` percentages are resolved **per axis** as CSS requires, so the panel's 2143×680 bottom sweep is a real ellipse again instead of a capsule with its arc 38px flatter. And gradients are baked into a texture shown through a rounded Mask instead of collapsing to their first stop — uploaded via `Texture2D.reset` + `uploadData`, because the `ImageAsset` route throws `texSubImage2D … Overload resolution failed` every frame. A third pass found two more: Creator **trims the transparent border off imported PNGs** and then `SizeMode.CUSTOM` stretches what is left to fill the box, so every icon came out ~8% too big (`sprite.trim = false` fixes it); and figma's stroke geometry is a **pre-cut band of width 2w** that expects the consumer to hide half of it — drawing the paths in array order left the whole band showing, i.e. every outline twice as thick, so paths are now drawn in three passes by `clip` like figma2unity does. With the shared design font on top, the means are **6.21→4.30 / 8.93→6.08 / 8.76→6.18 / 6.33→6.04**. Also implemented rather than declared away: `clip` via `Mask.Type.GRAPHICS_STENCIL` (follows the radius, and unlike Godot's `clip_children` it **nests**), `paths` drawn through `Graphics`, hard shadows and `borderAlign: outside` as sibling underlays, `text.wrap`, and per-corner radii. Still lost: blurred shadows. It also strict-typechecks against official `@cocos/creator-types` 3.8.3 (engine d.ts, decorators incl.) and **you can run that gate**: `cd tools/cocos-typecheck && npm ci && python3 check.py`, also in CI; it asserts zero errors **and** that planting a type error into the real source makes `tsc` report it. Motion is baked by its own `bake_motion.py`, sampled point-by-point against the other three backends (not yet watched in Play)

A fourth pass on 2026-08-05 found the last visible defect in the bottom bar: **Graphics' tessellator ignores winding order entirely** — `_expandFill` calls `Earcut(data, null, 3)` once per contour, with `holeIndices` always `null`. Reversing an inner contour, which is how canvas and SVG get holes, does nothing here, so every stroke ring that capture emits since v1.3 filled solid and each pill in the bottom bar came out painted in its own stroke colour. Holes are now punched with an inverted `GRAPHICS_STENCIL` mask instead, on the 3 of 97 paths that actually need one. **5.41 → 3.86/255.**

A fifth pass on 2026-08-05 measured against the **Figma export** rather than against the HTML build, and the same gap Unity had showed up here: **blurred shadows** were logged as a known-loss and simply not drawn. Being an interpreter this backend cannot bake at compile time, so it bakes at load time instead — the route it already uses for gradients: a rounded-rect coverage mask through three box passes (σ = blur/2), uploaded with `Texture2D.reset` + `uploadData`, shown through a `Sprite` with **`trim = false`** (Creator trims transparent borders off a texture, and a shadow is almost entirely transparent border — trimmed and then stretched to fill, the shadow comes out enlarged and misplaced). Outside text, the list screen went **1.34 → 1.13/255** against the design.
