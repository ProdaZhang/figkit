# 该不该动 · 该用哪个

> **先过闸门,再查表。** 目录里有 59 条效果,但**「不加动效」是一个正当的、常常最优的答案**,
> 不是失职。一个到处建议加动效的工具比没有更糟 —— 它产出的正是这份档要防的那种拖沓界面。

## 1. 闸门

### 第 0 关 · 先判类。这一步定了后面用哪套规则

| 类 | 是什么 | 例子 | 走哪套 |
|---|---|---|---|
| **① 功能 UI** | 控件的状态变化 | 弹窗、页切、按压、拖拽 | **过下面四关** |
| **② 循环** | 常驻、无限播放 | 呼吸、漂浮、跑马灯 | **不过频率关**(它不是被触发的)。只需:**弱** + **同屏 ≤ 3 处** |
| **③ 反馈** | 一次性、即时 | 飘字、顿帧、抖动、数字滚动 | **不过频率关**。只需:**越快越好** |
| **④ 演出** | 罕见、高价值的**兑现** | 抽卡出货、升星、进化 | **不过任何一关。不受 `dur-cap` 约束** |

> ⚠️ **频率表只管 ①,不管 ④。这是最容易搞反的一条。**
> **功能 UI 的动效是成本**(玩家一天见几百次,越短越好);**演出的动效是商品**(玩家就是为这一下
> 来的,看一百遍也要爽)。**拿频率表去砍出货演出,等于把商品当成本砍掉。**

### ① 功能 UI 的四关 —— 按顺序,过不了就停,并记下卡在哪关

**第 1 关 · 频率:玩家一天会看几次?**

| 频率 | 判决 |
|---|---|
| **100+ 次/天**(核心导航、主城↔战斗、普攻) | ❌ **驳回。永不加动效。** |
| **几十次/天**(hover、列表切换、常用开关) | ❌ 驳回,或只给**几乎察觉不到**的(快而轻) |
| **偶尔**(弹窗、抽屉、Toast、设置) | ✅ 可以 —— **标准动效** |
| **罕见 / 首次**(新手引导、空状态、成功、庆祝) | ✅ 可以 —— **「取悦预算」就住在这一档** |

> **高频操作是「取消资格」,不是「斟酌」** —— 一天重复几百次,动效只会让它显得慢、有延迟、
> 不跟手。(Raycast 的开关窗**没有任何动效**,那就是最优解。)

**第 2 关 · 目的:必须能用下面**其中一个词**说出来**

- **反馈** —— 告诉玩家「界面收到了」(按压缩放、长按填充)
- **空间一致** —— 说清「从哪来 / 到哪去」(Toast 从哪进就从哪出;面板从触发它的按钮长出来)
- **状态可读** —— 让状态变化看得懂(按钮形变、折叠展开)
- **防止突兀** —— 内容瞬间出现 / 消失 / 瞬移,中间没有桥
- **解释** —— 演示某个功能怎么用(仅新手引导 / 宣传)
- **取悦** —— **只允许在「罕见 / 首次」这一档**
- **兑现** —— 玩家**付出了资源或时间**,这是**回报的兑付现场**(出货、升星、领奖)。
  ⚠️ 这条是游戏独有的,工具型 UI 的动效词表里没有。**它不是「取悦」,它是玩家买的东西。**

> **「看着酷」不在名单上。** 说不出上面任一个词 → **驳回。**

**第 3 关 · 速度:压得进预算吗?**(天花板 = `dur-cap` 令牌)
> 如果这个效果**只有慢下来、张扬起来才好看**,它就过不了闸门。

**第 4 关 · 功能:动是帮忙还是添乱?**
> **玩家正在读、正在点的数据,不该为了风格而动。** 装饰性动效放在信息密集的功能区 = 添乱。

## 2. 场景 → 效果 · 正查表

> 你面前这个场景**长得像哪一行**,就用那一行的效果。

**功能 UI 的接缝(web / 游戏通用)**

| 你看到 | 该用 |
|---|---|
| 可点元素**没有按下态** | **按压反馈**(这是**缺陷,不是风格**) |
| **不可逆的破坏性操作**只用一次点击确认 | **长按确认** |
| 内容**瞬间**出现 / 消失 / 替换 | **缩放入场**(默认)· 罕见时刻才用**弹入** |
| 折叠区**啪地**弹开 | **折叠 / 展开** |
| 列表增删**没有过渡** | **布局动画**(FLIP) |
| 气泡 / 菜单**跟触发它的按钮没有视觉联系** | **原点感知**(居中弹窗**例外**) |
| 浮层**进出方向不一致** | **滑入**(进出对称、用比例不用绝对像素) |
| 一屏卡片 / 格子**唰地全出现** | **逐项入场**(总时长要压) |
| 可拖 / 可滑的东西**硬邦邦地吸附** | **拖拽** + **弹簧** + **吸附** |
| 列表滚到头**硬停住** | **橡皮筋**(硬停住 = 玩家以为卡了) |
| 同位置换图**很脏**(双曝光) | **交叉淡化** + **模糊遮掩** |
| 通知**来得比读得快** | **堆叠 Toast** |

**游戏的接缝(工具型 UI 的词表里一条都没有 —— 这半边只能自己来)**

| 你看到 | 该用 | 为什么 |
|---|---|---|
| **资源变了,但只弹了个 Toast** | **飞向目标** + **数字滚动** | 玩家心里唯一的问题是「**进我兜里了吗**」。Toast 回答不了 |
| **命中了,但只是掉血** | **顿帧** + **震屏** + **飘字**(**三者错开**) | 顿帧是打击感**最大**的来源,而且几乎免费 |
| **高价值时刻(出货 / 升星)是平的** | **仪式** / **出货演出** | 这是玩家**付了钱的兑现现场**。④ 类,**不受频率表管** |
| **空槽位 / 可领取 没有任何提示** | **呼吸**(同屏 ≤ 3 处) | |
| **技能 CD 只是灰掉** | **冷却扫描** | 时长来自玩法数据,**不归动效档** |
| **立绘 / 萌宠像贴图** | **漂浮**(相位错开) | 呼吸是**提示**(要你动手),漂浮是**氛围** |
| **加载是白屏 / 一个转圈** | **骨架屏**(布局已知时)· **场景转场**盖住加载 | 转场必须**并行**盖住加载,不是串行 |
| **升级 / 解锁 没有兑现感** | **高亮闪** + **数字滚动** | |
| **失败 / 拒绝 只有一行红字** | **抖动**(必须配红框 —— 减弱动效下要有替身) | |

**「取悦预算」住在哪**
> 只有**罕见、情绪高**的时刻 —— 首次、空状态、成功、庆祝、兑现 —— **才配得上过冲、慷慨的
> stagger、更长的节拍**。其余地方,**动效是成本**。

## 3. 反查 · 去哪找「该动却没动」

> 上一节是正查(我这个场景该用哪个);本节是反查(把界面扫一遍,哪儿缺动效)。
> ⚠️ **姿态是「克制」,不是「找活」。预期是驳回绝大多数候选。**
> **一条都没有是好结果** —— 直说「这个界面的动效已经够了」。

| 接缝 | 扫什么 | 撞到了给什么 |
|---|---|---|
| **反馈缺口** | 可点的东西**没有按下态** | **按压反馈**(这是缺陷,不是风格) |
| | 不可逆操作只用一次点击确认 | **长按确认** |
| **状态瞬移** | 条件渲染 / 显隐切换 / 内容替换**没有桥** | **缩放入场** |
| | 折叠区**啪地**弹开 | **折叠 / 展开** |
| | 列表增删**没有过渡** | **布局动画**(FLIP) |
| **空间故事缺失** | 浮层跟触发它的控件**没有视觉联系** | **原点感知**(居中弹窗例外) |
| | 进来和出去**走不同的路** | **滑入**(进出对称) |
| **齐刷入场** | 一屏卡片 / 格子**同时出现**(且该屏不是高频) | **逐项入场**(总时长要压) |
| **手势接缝** | 可拖 / 可滑的东西**硬邦邦地吸附**、滚到头**硬停住** | **拖拽** + **弹簧** + **吸附** + **橡皮筋** |
| **取悦预算被浪费** | **罕见 / 首次 / 兑现**的时刻做得干巴巴 | 这是**唯一**该给 ④ 演出的地方 |

> **figkit 用户注意**:前两行(按压缺口、状态瞬移)正是 `motion.py apply_defaults` 已经替你补掉的
> 那几处 —— 弹窗开合、按压、逐项入场、guard 失败。剩下的行要你自己判断。

## 4. 层次与聚焦 · 要不要打断心流

**暗化聚焦 vs 分离保流** —— 这是**「要不要打断心流」的判断**,不是视觉选择:

| 场景 | 做法 |
|---|---|
| **模态任务**(购买确认、二次确认、公告) | 配**暗幕** + 背景推后 → **明确打断**,玩家必须处理它 |
| **并行非阻塞面板**(侧栏、Tips、浮层信息) | **偏移 + 层级,但不加暗幕** → **不打断心流**,玩家可继续看背景 |
| **堆叠弹窗** | 每往上一层,父层**渐进加暗、推后** |

> 📌 **别把模态的暗幕套到并行面板上** —— 那等于告诉玩家「停下,先处理我」,而它其实不配。
> 📌 材质与阴影风格(毛玻璃 / 拟物 / 厚描边)**不归动效档**,归各项目的界面规范。

## 5. 多模态 · 动 + 声

> 游戏有音效,这条比 web 重要得多。

1. **因果性** —— 必须一眼看出**是什么触发了反馈**。绑在**真正的因果事件**上(按钮真的按下、
   物品真的落袋),且性格要配得上动作的物理感。
2. **和谐性** —— 视觉与音效**必须同一帧触发**。**延迟会直接毁掉整个错觉** —— 别让动效比音效慢半拍。
3. **有用性** —— 只在**有意义的时刻**给(成功 / 失败 / 提交 / 吸附)。
   **过度反馈会训练玩家忽略全部反馈。**

## 6. 性能 · 只动那两样

**跨引擎通则:只动「变换」和「不透明度」。** 这两样在所有现代渲染管线里都是**合成阶段**的活,
不触发布局与重绘;改尺寸 / 位置 / 边距会**每帧走完整条布局 → 绘制 → 合成**。要改形状或位置就上
`algorithms.md §6 FLIP`。

**帧预算**:60fps = 每帧 16.7ms(120fps = 8.3ms)。超了就丢帧,连续丢就是卡顿。
📌 只动变换 / 不透明度的意义就在这:它们**根本不进主线程的这 16.7ms 预算**。

- ✅ **发光用不透明度叠层**,别每帧重算阴影。
- ✅ **模糊要克制**(半径小、面积小),它在移动端很贵。
- ✅ 「即将要动」的提示(如 `will-change`)**只在真要动时加,别常驻** —— 常驻会一直占着显存,
  滥用反而更卡。

<details>
<summary>web 侧的具体条款(figma2html 后端适用)</summary>

- ❌ 别动 `width` / `height` / `margin` / `padding` / `top` / `left` —— 三步全触发(layout thrashing)。
- ❌ **`transition: all` 永远是缺陷** —— 会连带动到意料外的属性,且脱离 GPU。**写明具体属性。**
- ❌ **别在父元素上改 CSS 变量来驱动子元素 transform** —— 会让**所有**子元素重算样式。
  直接在元素自己身上设 `transform`。
- ✅ `filter: blur()` < 20px,别大面积(Safari 上很贵)。

**选型:transition / keyframes / WAAPI / 弹簧**

| 情形 | 用 | 为什么 |
|---|---|---|
| **可能被快速重复触发 / 中途改道**(页切、按压、Toast) | **`transition`** | **能从当前值重定向**;`@keyframes` 会从 0 重启 |
| **一次性播完即弃**(飘字、涟漪、高亮闪) | **`@keyframes`** | 不需要中途接管;`remove` 即回 0% |
| **② 循环 / ④ 演出** | **`@keyframes`** | 它们是**预定编排**,不需要接管 |
| **手势驱动 / 要继承速度** | **JS + 弹簧** | 只有弹簧能吃初速、能被抓回 |
| **要用 JS 编排预定动效** | **WAAPI**(`el.animate(...)`) | 别手写 rAF 去模拟 keyframes |
| **入场动效不想写 JS** | **`@starting-style`** | 纯 CSS 就能给「刚插入 DOM」的元素一个起始态 |

📌 **CSS 动画在主线程忙时比 JS 稳**(跑在合成线程)。**预定动效用 CSS,动态 / 手势用 JS。**

**三类只能靠脚本抓的静默失败**(不报错、不警告、控制台干干净净):

| 坑 | 症状 | 为什么骗人 |
|---|---|---|
| **`var()` 引用未定义变量** | 动效**整个消失** | 整条声明「在计算值时失效」被丢弃,退回 `all 0s ease`;而 CSS 本身没错、同规则其它属性照常生效 |
| **重复 `id`** | **点 A 却改了 B** | `getElementById` 只返回第一个 |
| **JS 找一个不存在的 `id`** | **整条初始化链全死** | `null` → TypeError → 后面全不执行;但页面静态部分照样渲染,看着很正常 |

`node --check` 抓不到这三类(全是运行时 / 语义问题);渲染截图也只抓得到「会改变布局」的那种 ——
**「点了没反应」在截图里和正常的一模一样**。配一个原型 linter,提交前跑。

**整页禁选中**:`body{ user-select:none }` + `.selectable{ user-select:text }` 白名单。
规律是**连点两下 = 双击 = 选中文字**,所以凡是可点、可拖、会被反复触发且带字的元素都会中招:
蹦出划词工具栏盖住界面、拖到一半选区一起来手感全废。
📌 它**不能替代**指针按下时的 `preventDefault()` —— 前者管选中,后者还管原生拖图。手势场景两个都要。
</details>

## 7. 无障碍 · 减弱动效不是零

- **减弱动效 = 更少、更温和,不是零。** 保留有助理解的淡入淡出;去掉位移 / 缩放 / 视差。
- **按类分级**:
  - **② 循环最该关** —— 常驻晃动最易致不适。
  - **视差必关** —— 它是**前庭不适的头号来源**。
  - **③ 反馈可缩短**(如飘字减半)。
  - **④ 演出降级为静态终态,别砍掉** —— 它承载的是**信息**(你得到了什么),不是装饰。
  - **否定信息必须有非动效替身**(抖动 → 红框 / 红字)。**关了动效就等于没告诉玩家。**
- **hover 门控**:触屏没有 hover,但**原型是在桌面看的**,hover 态对评审有价值 →
  **加了就必须门控**(`@media (hover:hover) and (pointer:fine)`),别让真机误触发。
- 避免:全屏移动背景、约 0.2Hz 的慢循环振荡、突兀的亮度跳变。
- **大物件长距离移动时让它半透明一点**;大面板整体重定位时,**移动中淡出、落定后淡回来**。
  大块实心色高速掠过视野是不适的来源。

## 8. 十条不可协商(违反即缺陷)

1. **动效有正当理由** —— 说得出第 2 关的**七选一**
2. **频率匹配** —— 100+ 次/天 → **不动画**(但**别拿这条去砍 ④ 演出**)
3. **入场 / 出场用 `ease-out` 或自定义曲线** —— UI 上的 `ease-in` = 缺陷(**唯一例外:飞向目标**)
4. **① 功能 UI < `dur-cap`**
5. **原点与物理性正确** —— 不 `scale(0)`;Tips 从触发器长出;模态居中是对的
6. **可打断** —— 快速触发 / 手势 → 过渡或弹簧,不是关键帧
7. **只动变换与不透明度**
8. **无障碍** —— 减弱动效 + hover 门控
9. **非对称进出** —— 决策慢、响应快(出场比入场快)
10. **内聚** —— 动效性格和组件、和产品一致;**数值全走令牌,不硬编**

### 一眼判死(见到即改)

`transition: all` · `scale(0)` 入场 · UI 上的 `ease-in` · UI 时长 > `dur-cap` 且无理由 ·
Tips 绕自身中心展开 · 快速触发的东西用关键帧 · 动布局属性 · 位移动效没有减弱动效分支 ·
没门控的 hover · 按下与松手同速 · 一组元素齐刷出现(该 stagger)· **写了按下态却没写过渡** ·
**代码里出现裸数值而不是令牌**

## 9. 补救优先级(提修法时,靠前的先试)

> **顺序本身就是观点**:多数动效问题的最优解在**前两阶**,不是最后一阶。**别一上来就调曲线。**

| # | 阶 | 什么时候 |
|---|---|---|
| 1 | **删掉** | 高频 / 说不出目的 / 快捷键触发的 |
| 2 | **减弱** | 时长砍短、幅度调小、少动几个属性 |
| 3 | **换曲线** | `ease-in` → `ease-out` / 令牌曲线 |
| 4 | **修原点与物理** | 枢轴指向触发器;`scale(0)` → `scale(.95)` + 淡入 |
| 5 | **让它可打断** | 关键帧 → 过渡;手势 → 弹簧 |
| 6 | **挪上合成层** | 布局属性 → 变换 / 不透明度 |
| 7 | **改成非对称** | 决策段放慢、响应段抢拍 |
| 8 | **抛光** | `blur-mask` 遮双曝光、stagger |
| 9 | **无障碍与内聚** | 减弱动效、hover 门控、性格对齐 |

## 10. 四个老手法(用在 ④ 演出,别用在 ① 功能 UI)

传统动画的手法,**只在「取悦预算」里花**(罕见 / 首次 / 兑现)。用在高频功能 UI 上 = 拖沓。

| 手法 | 是什么 | 用在哪 |
|---|---|---|
| **预备动作 Anticipation** | 动之前先**朝反方向小蓄力** —— 挥拳先收臂 | 仪式起手、大招前摇、弹入(`ease-pop` 的 y1>1 就是它的近亲) |
| **跟随 Follow-through** | 主体停了,**附属部分还在动一下才停** —— 尾巴、披风、余韵 | 仪式收束、飘字尾巴、卡牌落定后的轻晃 |
| **挤压拉伸 Squash & stretch** | 变形传达**重量、速度、弹性** —— 落地压扁、加速拉长 | 飞向目标的落袋、萌宠待机、Q 弹入场 |
| **速度感 Motion blur / 拉伸** | **极快的移动**给一点模糊或沿运动方向拉长 | 飞行体、冲刺、大招位移 |

> 📌 **这四个都会「加时长」** —— 所以它们天然属于 ④ 演出。**别拿去给弹窗加预备动作。**
> 📌 挤压拉伸要**保体积**(压扁就得变宽),否则读作「缩放」不是「挤压」。
> 📌 **速度感解决的是「每帧跳太远」** —— 移动快到每帧位移超过感知阈值时,眼睛看到的是**一串
> 断点**(频闪),不是一条轨迹。糊一下 / 拉一下就把断点连成线了。**别用真模糊做**(每帧重算,贵);
> 沿运动方向拉伸 / 斜切是免费的。
